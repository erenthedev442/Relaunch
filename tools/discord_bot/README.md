# Legendary Hunter — Discord bots

This directory has **two** independent Discord integrations. Run either, both,
or neither — they share nothing but the catalog + DB helpers.

| Script | Type | What it's for |
|---|---|---|
| `discord_bot.py` | One-way **webhook notifier** (polled by Task Scheduler) | Pushes rank-ups, capstones, HNM King spawns, weekly sweeps, daily/weekly digests, and server patch-notes into a channel. No bot token. |
| `token_bot.py` | Two-way **slash-command bot** (long-lived daemon) | Answers `/online`, `/huntrank`, `/leaderboard`, `/prestige`, `/lfg`; lets players `/register` their character and (optionally) syncs Discord roles by rank. Needs a bot token. |

Both read the same `catalog.json` (single source of truth, regenerated by
`refresh-site.bat`) and the same `_db.py` connection, so their rank/guild data
can never disagree. **Neither runs until you set it up and start/schedule it.**

---

## Webhook notifier (`discord_bot.py`)

Webhook-based, polled, idempotent. Posts rank-ups, capstone achievements,
weekly Hunt Board sweeps, and daily/weekly digests to a Discord channel.

## What it posts

| Event | Trigger | Cadence |
|---|---|---|
| `:shield: <player> has risen to Veteran of the AF Hunters' Guild!` | Player crosses a guild rank threshold | Within 5 min of the event |
| `:trophy: TRINITY HUNTER` | Player earns Grandmaster in all 3 Reforge guilds | One-time per player |
| `:crown: APEX HUNTER ACHIEVED` | Player earns Grandmaster in all 4 guilds | One-time per player |
| `:star: <player> swept the Weekly Hunt Board!` | Player clears all 5 weekly objectives | Up to once per week per player |
| `:sparkles: <player> reached N lifetime Ascensions` | Player crosses a Prestige milestone (1/10/25/50/100/…) | Once per milestone |
| `:fire: <player> is on an N-day login streak` | Player's best login streak crosses 30/100/365 days | Once per milestone |
| `:dragon: <King> has spawned in <zone>!` | A timed HNM King transitions to UP | Once per spawn |
| `:scroll: Server update — N new changes` | New commits land in the server repo (`D:\server`) | Within 5 min of a commit |
| **Daily Recap** | Once per UTC day, after `DAILY_DIGEST_HOUR_UTC` | Daily |
| **Weekly Recap** | Once per ISO week, on `WEEKLY_DIGEST_DAY` after the hour | Weekly |

## Setup (5 minutes)

### 1. Create the Discord webhook

1. Open the channel you want notifications in.
2. **Channel Settings** → **Integrations** → **Webhooks** → **New Webhook**.
3. (Optional) Name it "Legendary Hunter" and set an avatar.
4. Click **Copy Webhook URL**. It looks like
   `https://discord.com/api/webhooks/123456.../abcDEF...`.

### 2. Configure the bot

```
cd D:\server\tools\discord_bot
copy config.example.py config.py
notepad config.py
```

Paste your webhook URL into `WEBHOOK_URL`. Save.

### 3. Test it

```
python D:\server\tools\discord_bot\discord_bot.py
```

First run bootstraps state silently — no posts on the first invocation,
even if veterans already have Trinity / etc. The script just records
the current state as a baseline. Future runs diff against that baseline.

To verify the webhook works, kill any custom NM in-game to push someone's
rep over a rank threshold, then run the script again — you should see the
rank-up message land in Discord within a few seconds.

### 4. Schedule it

**Easiest:** double-click **`webhook_bot_control.bat`** in this folder — a little
menu that installs the schedule for you. **[1] Turn ON / Install** creates a Task
Scheduler job that runs the bot every 5 minutes (no `--commit` arg) and fires one
pass now; **[2]** disables it, **[3]** runs a single pass, **[4]** restarts. It
mirrors the AH market-maker control panel, and warns if `config.py` is missing.

Or do it by hand — Windows Task Scheduler, every 5 minutes:

```
Program:    python.exe
Arguments:  D:\server\tools\discord_bot\discord_bot.py
Start in:   D:\server
Trigger:    Daily, repeat every 5 minutes, indefinitely
```

The script is idempotent — running it more often is fine (it just no-ops
when nothing has changed). 5 minutes is the sweet spot for "real-time-ish"
without hammering the DB.

## HNM spawn alerts & patch-notes

Two extra per-event feeds, both on by default and configured in `config.py`:

- **Timed HNM King spawns** (`HNM_ALERTS_ENABLED`). When a timed King (Fafnir,
  Adamantoise, Behemoth, …) goes UP, the bot posts a `:dragon:` rally. It reads
  the `[HNM]<Name>` pop-time ServerVars directly and names them from
  `catalog.json`'s exported HNM roster, so the alert feed can't drift from the
  in-game module or the HNM doc page. Each distinct spawn fires exactly once;
  kills/respawns are tracked silently. HQ land kings are QM-pop (no timer) and
  aren't tracked. Optional `PING_ROLE_ON_HNM` / `PING_HERE_ON_HNM`.
- **Server patch-notes** (`PATCH_NOTES_ENABLED`). New commits to the server repo
  (`D:\server`) are cross-posted as a `:scroll: Server update` list — the same
  commit-subject filter the website changelog uses (merges/automated commits
  skipped). `PATCH_NOTES_MAX` caps how many a single post lists (the rest
  collapse into "…and N more"); optional `PING_ROLE_ON_PATCH`.

Both bootstrap silently on the first run (current King states + current HEAD are
recorded as the baseline) so enabling them never floods the channel with history.

## State file

`state.json` (gitignored) tracks:

- Last-seen rank/title/sweep counts per player → for diffing
- Last digest timestamps → so daily/weekly don't double-fire
- `bootstrapped: true` after first run → so historical events aren't
  re-announced if you reset state somehow

Safe to delete `state.json` if you ever want to re-bootstrap from current
DB state (e.g. after a major catalog rebalance). The next run will set
the new baseline silently.

## Troubleshooting

**"WEBHOOK_URL is not set"** — copy `config.example.py` → `config.py` and
edit it.

**"DB unreachable"** — the bot uses the same connection as
`tools/docgen/`. Set `LEGENDARY_LIVE_ROOT=D:\server` in your environment,
or make sure `tools/docgen/_db.py` is configured for your DB.

**"HTTP 401"** — webhook URL is invalid or has been revoked. Create a
new webhook in Discord and paste the new URL.

**"HTTP 429"** — Discord rate-limited you. The script exits and retries
on the next scheduled run.

**No posts even after a real event** — check that `MIN_RANK_TO_ANNOUNCE`
isn't filtering out the rank. Default 2 = Journeyman+. Set to 1 to see
every rank-up including Apprentice.

## What the webhook notifier doesn't do

- **Slash commands** — the webhook is one-way (server → Discord). For
  `/huntrank` style queries *inside Discord*, run the companion
  `token_bot.py` (below). The in-game `!huntrank` and `!weekly` commands
  also cover this from the game side.
- **Two-way interaction** — players can't reply to a webhook post and
  trigger in-game effects. Out of scope for the simple webhook design;
  the token bot reads live data but is also read-only into the game.

## Two-way slash-command bot (`token_bot.py`)

A second, **optional** bot. Where the webhook notifier *pushes* events out,
this one *answers questions* — players type slash commands in Discord and
get live data back, pulled from the same `catalog.json` + `_db.py` the
notifier uses, so the two can never disagree.

It needs a real Discord application + bot token and runs as a **long-lived
daemon** (not polled by Task Scheduler like the webhook bot).

### Commands

| Command | What it answers |
|---|---|
| `/online` | How many players are online right now, and who (opt-outs hidden). |
| `/huntrank [player]` | A player's guild rank + Hunt Mark rep across all four Reforge guilds. Omit the name to use your linked character. |
| `/leaderboard <board>` | Top 10 for Hunting League kills, lifetime Hunt Marks, lifetime Infamy, or Ascensions. |
| `/prestige [player]` | A player's total Ascensions and per-job Prestige levels. Omit the name to use your linked character. |
| `/register <player>` | Link your Discord account to your in-game character. |
| `/whoami` | Show which character you're linked to. |
| `/unregister` | Remove your character link. |
| `/lfg [activity]` | Posts a Looking-For-Group rally (optionally @-pinging `LFG_ROLE_ID`). |

Read-only **against the game DB** — the only thing this bot writes is
`links.json` (account links, gitignored). Players who opted out of leaderboards
in-game (`Leaderboard_OptOut`) are hidden from `/online` and `/leaderboard` here too.

### Setup

#### 1. Install discord.py

```
pip install -U discord.py
```

(Python 3.9+.) The webhook notifier has no dependencies; this one needs
`discord.py` 2.x for slash-command support.

#### 2. Create the Discord application + bot

1. Go to <https://discord.com/developers/applications> → **New Application**.
2. Name it (e.g. "Legendary Hunter"), open the **Bot** tab.
3. **Reset Token** → **Copy**. This is your `BOT_TOKEN` — keep it secret
   (`config.py` is gitignored).
4. No privileged intents are required — leave Presence / Server Members /
   Message Content **off**. The bot only uses slash commands.

#### 3. Invite the bot to your server

1. **OAuth2** → **URL Generator**.
2. Scopes: check **`bot`** and **`applications.commands`**.
3. Bot Permissions: **Send Messages** + **Embed Links** is enough.
4. Open the generated URL, pick your server, **Authorize**.

#### 4. Configure

Edit the same `config.py` you made for the webhook bot (the token-bot keys
live at the bottom of `config.example.py`):

```
BOT_TOKEN   = "<the token from step 2>"
GUILD_ID    = 123456789012345678   # your server ID, as an int (no quotes)
LFG_ROLE_ID = ""                   # optional role to @-ping on /lfg
```

To get `GUILD_ID`: enable **Developer Mode** (Discord Settings → Advanced),
right-click your server icon → **Copy Server ID**.

For optional automatic role-by-rank, also set `ROLE_SYNC_ENABLED` / `ROLE_SYNC`
— see **Rank role sync** below.

#### 5. Run it

```
set LEGENDARY_LIVE_ROOT=D:\server
python D:\server\tools\discord_bot\token_bot.py
```

On startup it registers its slash commands to your one guild (`GUILD_ID`),
so they appear **instantly** — no waiting for Discord's global propagation.
You should see `Logged in as …` and the commands show up when you type `/`
in the channel.

#### 6. Keep it running (hosting)

Unlike the webhook bot, this one must stay up to answer commands. Two easy
options on Windows:

- **NSSM (recommended).** Install [NSSM](https://nssm.cc/), then:
  ```
  nssm install LegendaryTokenBot "C:\Path\to\python.exe" "D:\server\tools\discord_bot\token_bot.py"
  nssm set LegendaryTokenBot AppDirectory D:\server
  nssm set LegendaryTokenBot AppEnvironmentExtra LEGENDARY_LIVE_ROOT=D:\server
  nssm start LegendaryTokenBot
  ```
  It now runs as a Windows service, auto-restarts on crash, and survives
  reboots.
- **Task Scheduler, "At startup."** Create a task that runs
  `python.exe D:\server\tools\discord_bot\token_bot.py`, **Start in**
  `D:\server`, trigger **At startup**, and set it to restart on failure.

### Account linking (`/register`)

Players link their Discord account to their in-game character once with
`/register <character>`. After that, `/huntrank` and `/prestige` default to that
character when called with no name, and rank role sync (below) can grant their
roles automatically.

- Links live in **`links.json`** next to the bot (gitignored — it's player data,
  never committed). The bot stays strictly read-only against the *game* DB.
- **Trust-based claim (MVP):** anyone can claim any *unclaimed* character — there's
  no in-game ownership proof yet. **Char-uniqueness is enforced**, though: a
  character can only be linked by one Discord member at a time, so a claimed main
  can't be hijacked. To settle a dispute, a GM hand-edits `links.json` (a plain
  `{ "<discord_id>": {"charid", "charname"} }` map) and it takes effect on the
  next command / sync. A future hardening step is an in-game confirmation code,
  which needs a DB-write path this read-only bot deliberately avoids today.
- `/whoami` shows the current link; `/unregister` removes it. Replies are
  ephemeral (only the caller sees them), so linking doesn't spam the channel.

### Rank role sync (optional)

The bot can grant/remove Discord roles by Hunter's Guild capstone tier, every
~10 minutes, for every linked player. **Off by default.** Enable it in `config.py`:

```python
ROLE_SYNC_ENABLED = True
ROLE_SYNC = {
    "apex":        "111111111111111111",   # top rank on all four guilds (rarest)
    "trinity":     "222222222222222222",   # top rank on three guilds
    "grandmaster": "333333333333333333",   # top rank on at least one guild
}
```

- Map any subset — leave a value `""` to skip that tier. Roles **stack**: an Apex
  hunter qualifies for all three at once, so map all three to layer them, or map
  only `apex` for a single elite role.
- It only ever touches the roles you list — other roles are never added/removed.
- **Discord side:** give the bot **Manage Roles**, and drag the bot's own role
  **above** each role it assigns (Server Settings → Roles), or Discord rejects the
  change. No privileged intents needed — members are resolved via the REST API
  (`fetch_member`), so you don't toggle Server Members in the portal.
- Tiers come from the same live data the webhook notifier uses for its Trinity /
  Apex announcements (`Title_Trinity_Hunter`, `Title_Apex_Hunter`, and guild rep
  vs. the top rank threshold), so roles and announcements can't disagree.

### Should I just run one bot?

You *can* run only the token bot and skip the webhook notifier — but they do
different jobs. The webhook bot **pushes** rank-ups/capstones/digests into a
channel unprompted (great for hype); the token bot **answers** when asked.
Most servers want both: notifier for announcements, token bot for lookups.
They share the catalog + DB layer, so there's no duplication of truth — just
two processes. Run whichever fit your needs; neither requires the other.

### Troubleshooting

**Slash commands don't appear** — make sure you invited the bot with the
**`applications.commands`** scope (step 3) and that `GUILD_ID` matches the
server you're typing in. Commands sync to that one guild on startup.

**"No module named 'discord'"** — run `pip install -U discord.py` in the
same Python environment you launch the bot with.

**"BOT_TOKEN is not set" / "GUILD_ID is not set"** — fill them in `config.py`
(see step 4). `GUILD_ID` must be an integer with no quotes.

**Bot is online but every command says "DB unreachable"** — same DB wiring
as the webhook bot: set `LEGENDARY_LIVE_ROOT=D:\server` in the bot's
environment (the NSSM `AppEnvironmentExtra` line, or `set` before launching).

**"PrivilegedIntentsRequired"** — you don't need privileged intents; make
sure none are toggled on in the Developer Portal **and** the code requests
only default intents (it does, out of the box).

**Role sync isn't granting roles** — three things to check: (1)
`ROLE_SYNC_ENABLED = True` and the tier's role ID is filled in `ROLE_SYNC`;
(2) the player ran `/register` (only linked players sync — `/whoami` confirms);
(3) the bot has **Manage Roles** and its own role sits **above** the target roles
in Server Settings → Roles. Sync runs every ~10 min and on startup, and skips
members/roles it can't action rather than crashing — so a perms/hierarchy problem
fails silently; fix the hierarchy and it self-heals on the next pass.

## LinkShell → Discord bridge (`ls_bridge.py`)

A **third**, optional integration: mirror **one** in-game LinkShell's chat into a
Discord channel in **near-real time (~3s)**, one-way (game → Discord). No bot
token, no C++ change, no rebuild — it rides the server's **built-in chat audit**.

### How it works

When `AUDIT_CHAT` + `AUDIT_LINKSHELL` are on, the map server INSERTs every
LinkShell line into the `audit_chat` table (`speaker, type='LINKSHELL', lsName,
message, datetime`, auto-increment `lineID`). The bridge is a small daemon that
tails that table by `lineID`, keeps only your chosen shell, and POSTs each new
line to a Discord webhook as `**Speaker**: message`.

The C++ stores the **decoded** shell name in `lsName`, so one shell is matched
whether members equip it as LinkShell1 **or** LinkShell2.

**Safety:** every post sets `allowed_mentions: {parse: []}` — a player typing
`@everyone` / `@role` in LinkShell can **never** ping your Discord server.

### Setup

**1. Turn on the audit (server side — box-only, `settings/*.lua` is gitignored):**

In `settings/map.lua` on the box:
```lua
AUDIT_CHAT      = true,
AUDIT_LINKSHELL = true,
```
Make sure the `audit_chat` table exists (`sql/audit_chat.sql`), then **restart
the map** (`xi_map`) — these settings are read at startup. Until this is done,
`audit_chat` stays empty and the bridge has nothing to post.

**2. Create the Discord webhook** for the channel you want LS chat in
(Channel → Integrations → Webhooks → New Webhook → Copy URL). Use a channel
*separate* from the hunter notifier unless you want them mixed.

**3. Configure:**
```
cd /home/azureuser/server/tools/discord_bot
cp config.example.py config.py     # if you don't already have one
nano config.py
```
Set:
```python
LS_BRIDGE_WEBHOOK_URL = "https://discord.com/api/webhooks/…"
LS_BRIDGE_NAME        = "Legendary"     # the exact in-game shell name
```

**4. Test one pass:**
```
python3 ls_bridge.py --once
```
The **first** run baselines at the newest `lineID` and posts nothing (so it
never floods the channel with history). Say something in that LinkShell in-game,
then run `--once` again — the line should appear in Discord.

**5. Run it as a service** (keeps it alive + restarts on reboot/crash):
```
sudo cp ls_bridge.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now ls_bridge.service
journalctl -u ls_bridge.service -f
```
(If your `pymysql` is in a venv rather than system Python, point the unit's
`ExecStart` at that venv's `python` — see the comments in `ls_bridge.service`.)

### Notes & limits

- **One-way only.** Discord → game would need an in-game message-inject path
  (a DB write / IPC the bridge deliberately avoids). Out of scope for v1.
- **One shell per bridge.** To mirror a second shell to a second channel, run a
  second copy with its own `config.py` + webhook (or extend `LS_BRIDGE_NAME` to
  a list — easy follow-up if you want it).
- **Auto-translate phrases** show as `�` (they're multi-byte FFXI codes, not
  UTF-8). Plain text comes through fine.
- `ls_bridge_state.json` (gitignored) holds the last-bridged `lineID`. Delete it
  to re-baseline from the current newest line.
