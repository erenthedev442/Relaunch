The one rule that explains "restart" timing

Pure Luacatalogs, commands, plain scripts → live FileWatcher hot-reloads instantly, NO restart.  sync-lua-to-azure
Override / SQL / settingsaddOverride & onGameIn modules, DB rows, gameplay knobs → only apply on a restart.  deploy-no-rebuild
C++ (src/)engine / crash fixes → need a rebuild + restart.  deploy-everything

↳ This is why tonight's crash fixes are staged but not live — they're C++ + override changes, so they wait for a restart you haven't run yet.

Typical sequences

Quick content tweak  › edit in D:\server › sync-lua-to-azure.bat › live in seconds, no restart
SQL / new module  › edit › (optional local test) › deploy-no-rebuild.bat › ~5–10 s restart, live ~2 min
C++ / crash fixes / big release  › edit › deploy-everything.bat › build ~10 min › one ~5–10 s restart + GitHub backup + site publish
Edit happens in one place (D:\server). Pushing is just "pick the lightest button that covers what changed." A restart is the only thing players feel — and only override/SQL/C++ changes need one. The occasional unprompted reboot is the Azure Spot eviction (~13 h, self-heals ≈2 min), not your deploy.
